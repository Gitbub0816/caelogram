# Orbital surface direction

THESIS: An inspection instrument for a real codebase. The data, rather than a background image, supplies the celestial objects.
OWN-WORLD: Neutral charcoal/slate #111213, platinum text, gold selection, rust, muted sage and warm mauve region colors. Textured file bodies, emissive high-incoming components, sparse dependency filaments. No blue.
STORY: Repository and commit first; choose Orbit, Heatmap, or Components; approach a body and inspect its evidence; illuminate a task; progress to a reviewable changeset.
FIRST VIEWPORT: Compact repository facts above a large orbital viewport, direct controls and persistent selected-component evidence at right. No promotional kicker, fabricated activity, or headline metric cards.
FORM: Extension of the user's established visual world. No concept roll or generated comp; the user's no-blue palette and request for both views are binding. The four reference images inform celestial depth, not literal star density or their blue hues.

Built following pbakaus/impeccable and emilkowalski/skills (emil-design-eng). Review focuses on user requirements and actual data, with the craft-floor and reduced-motion principles applied to the instrument frame.
